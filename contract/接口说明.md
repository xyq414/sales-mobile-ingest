# recording contract v1 接口说明

## 消费边界

下游只能消费可配置 `data_root` 下的 `ready/recordings`。一个完成对象由同一 basename 的原始媒体与 JSON sidecar 构成，例如：

```text
ready/recordings/20250115_101530_8ed3c2f1a4b5.m4a
ready/recordings/20250115_101530_8ed3c2f1a4b5.json
```

JSON 最后原子出现，是 ready commit signal。消费者不得把“只有媒体、没有 JSON”的项目视为可消费对象；这覆盖进程在媒体发布与 sidecar 提交之间中断的极小窗口。

下游不需要、也不应依赖手机品牌、MTP 路径、Windows 盘符或手机文件名规则。`source_relative_path` 仅为可审计 provenance，不是消费路由。

## 字段含义与可靠性

| 字段 | 含义 |
| --- | --- |
| `schema_version` | 固定为 `recording-contract/v1`。 |
| `recording_id` | `rec_` 加媒体原始字节 SHA-256；内容相同则 ID 相同，可复算且用于最终去重。 |
| `source_type` | 固定为 `phone_call_recording`。 |
| `device_vendor` / `device_model` | 由设备显示名称判断；没有可靠证据可为 `null`。 |
| `source_relative_path` | 手机存储根下的相对路径；没有 Windows 绝对路径。 |
| `original_*` / `source_*` | 复制前观察到的原始文件信息。MTP 未能可靠提供 modified time 时为 `null`。 |
| `recorded_at` | 命名所用时间。优先可严格解析的文件名时间，再用 source modified time，最后 import time。 |
| `recorded_at_source` | 明确说明上述时间证据来源，绝不把猜测包装成通话事实。 |
| `phone_number` / `contact_name` / `duration_seconds` | v1 不做模糊解析，无法可靠获取时为 `null`。 |
| `call_direction` | v1 未可靠识别时为 `unknown`。 |
| `sha256` | 本机 staging 文件完成复制后计算的 SHA-256。 |
| `media_filename` | 在 ready 中实际存在的原媒体文件。 |
| `imported_at` | 本机导入时间。 |
| `ingest_adapter` | `oppo-v1` 或 `generic-call-recording-v1`，用于观测适配来源。 |
| `ingest_status` | 发布完成时固定为 `ready`。 |

媒体不会在 v1 中转码。contract 标准化的是对象身份、目录、命名、元数据和提交语义，而非音频编码。

`duration_source` 是向后兼容的可选补充字段；新导入对象在 WPD 可靠报告时长时标为 `wpd`，否则标为 `unknown`。旧 sidecar 没有该字段仍符合 v1 schema。

电话录音成功发布后，采集器还会自动产生给下游使用的第二层事件 JSON；语义和 schema 见 [通信事件接口说明.md](通信事件接口说明.md)。
