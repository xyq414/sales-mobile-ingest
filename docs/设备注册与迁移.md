# Device Registry、销售归属与 legacy migration

## Enrollment

registry 位于 gitignored state v2。`device_id` 是本机随机 UUID，不是手机序列号。Windows Shell Path 只作为 observed alias，经 SHA-256 后保存在 registry；显示名/vendor/model 仅用于操作员辨认，不参与自动合并。精确 alias 唯一命中才重用 enrollment；新 alias 或 alias ambiguity 保持 unresolved/unassigned。

```powershell
python -m sales_mobile_ingest list-devices --discover
python -m sales_mobile_ingest show-device --device-id "<dev_...>"
```

## Effective-dated assignment

assignment interval 为 `[effective_from, effective_to)`，同一设备不允许 overlap。PhoneCall 按 `occurred_at` 查询区间，而不是按 import time 或当前持有人。

```powershell
python -m sales_mobile_ingest assign-device --device-id "<dev_...>" --salesperson-id "S001" --salesperson-name "张三" --effective-from "2026-01-01T00:00:00+08:00"
python -m sales_mobile_ingest end-device-assignment --device-id "<dev_...>" --effective-to "2026-10-01T00:00:00+08:00"
python -m sales_mobile_ingest assign-device --device-id "<dev_...>" --salesperson-id "S008" --salesperson-name "李四" --effective-from "2026-10-01T00:00:00+08:00"
```

命令会重新计算已有 PhoneCall 的 attribution，保持 call ID 不变。操作员不需要编辑 `config.local.json`、state 或源码。

## State/legacy compatibility

首次加载 `ingest-state.json` v1 时，系统先在同一 private state 目录创建 `ingest-state.v1.<UTC>.backup.json`，再以 atomic replace 写 v2。旧 imports/sources/recording IDs/event IDs/cloud publication state 原样保留。

旧 `config.local.json` 的单 salesperson 只在以下条件全部成立时自动迁移：加载的是 v1 state；历史 alias 只能唯一解析为一个 device；已有 CallLog/recording 提供可证明的最早 effective time。迁移产生 `legacy_config_migration` assignment 和 private migration evidence/config backup。没有时间边界时为 `PENDING_TIME_BOUNDARY`；多个 device 时为 `BLOCKED_AMBIGUOUS`，不得猜测。

rollback 不删除新 state 或 ready artifacts：停止进程，保留当前 v2 文件，然后将私有 v1 backup 复制为单独恢复输入并运行旧版本。已发布 cloud v1 包从不在 migration 中重写。生产 rollback 前应先备份整个 gitignored data root。
