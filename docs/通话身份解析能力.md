# 通话身份解析能力

最后真实核验：2026-08-19。本文只陈述当前 OPPO A6 Pro 5G 的一个本机样本与普通 USB/MTP/WPD 传输模式的事实；不把它推广为所有 ColorOS 或 Android 设备的结论。

## 当前结论

当前这一条真实 OPPO 电话录音**未能可靠取得对方电话号码**。真实 event 保持：

| 字段 | 当前真实值 |
| --- | --- |
| `phone_number_raw` | `NULL` |
| `phone_number_normalized` | `NULL` |
| `phone_number_source` / confidence | `unknown` / `unknown` |
| `contact_name` | `NULL` |
| `call_direction` | `unknown` |
| `occurred_at_source` | `wpd_modified_at`（不是确定的通话发生时间） |
| `duration_source` | `wpd` |

`investigate-identity` 会对唯一 ready recording 执行受限只读调查。原始文件名、WPD property 值、音频 tag 值和邻近对象名称只写入 gitignored 的 `data_root/diagnostics/identity-investigation/*.raw.json`；命令输出及 `*.summary.json` 不包含这些原始敏感值。

## 方案 A：录音自身信息

当前样本结果：`DIRECT_RECORDING_PHONE_ID_NOT_FOUND_IN_CURRENT_SAMPLE`。

| 检查面 | 真实观察 | 号码结果 |
| --- | --- | --- |
| 原始文件名 | 仅记录了去标识化结构：basename 长度 19、一个 10 位数字段、`-` 分隔、无可严格解析的 datetime token | 没有符合保守电话规则的 token；10 位数字不能被当作对方号码。 |
| WPD / Shell | 可取得 `System.FileName`、扩展名、title/artist/album、size、modified time、duration、编码码率/采样率等；没有 `System.DateCreated`；Shell details columns 为 0 | 已检查可取得的身份相关属性，未发现号码候选；非空 title/artist/album 不被推断为联系人。 |
| MP3 内部 metadata | 本机只读 ID3v2 probe：未发现 ID3 tag | 没有号码、联系人或方向。 |
| 同目录 | 只枚举该 source 的直接父目录，观察到 1 个对象、无额外文件或目录 | 没有 sidecar、manifest 或可关联 metadata。 |

因此当前没有启用任何 OPPO filename-number parser，也没有改写真实 event。未来如果多份真机样本出现同一可验证格式，最多先以 `REAL_SAMPLE_PROVISIONAL` 引入，且需保留原始值、规范化值、source、confidence，并与其他证据交叉验证。

## 方案 B：通话记录关联

当前结果：`CALL_LOG_NOT_EXPOSED_VIA_CURRENT_MTP_WPD`。

本机对当前 WPD portable-device 根和唯一 storage 的第一层公开对象进行了有界读取：1 个 storage、14 个首层对象；没有暴露 call-history object、contacts object 或 backup/export object。此结论的准确含义是：**当前 sales-mobile-ingest 所使用的无侵入 USB/MTP/WPD 链路没有公开可供读取的通话记录对象**；并不表示手机没有通话记录，也不表示不存在其他需要用户操作或权限的导出方式。

Android 的正式 CallLog API 是应用内 `ContentResolver` 路线，`CallLog.Calls` 明确要求 call-log 权限；`READ_CALL_LOG` 是危险且受限制的权限。[Android CallLog API](https://developer.android.com/reference/android/provider/CallLog.Calls) [Android permission reference](https://developer.android.com/reference/android/Manifest.permission.html) 同时，Android 将 USB “文件传输”描述为 MTP 文件传输模式，而非向 Windows 暴露 CallLog provider。[Android developer options](https://developer.android.com/studio/debug/dev-options)

所以当前真实 190.028 秒录音无法做 call-record correlation：不是“时间附近找不到唯一通话”，而是在关联算法之前就缺少可读取的 call-log row（号码、开始时间、方向、联系人）。没有伪造 call-log reader 或匹配结果。

## 方案 C：Android CallLog companion feasibility probe

本轮新增的是 `android/calllog-probe`，它是一次性 debug feasibility probe，不是 production companion，也没有接入 Windows watcher 或 `ready/events`。Android module 的 package 是 `com.salesmobileingest.calllogprobe`，`targetSdk`/`compileSdk` 均为 36；编译出的 APK 静态检查只声明了 `android.permission.READ_CALL_LOG`，没有 `INTERNET`、`WRITE_CALL_LOG`、`READ_CONTACTS`、外部存储、拨号器或后台服务权限。

Windows 本机已自动补齐并真实用于构建的最小命令行工具链：JDK 17、Android SDK Platform 36、Build-Tools 36.0.0、Platform-Tools/ADB 和 Gradle wrapper。它们仅在 gitignored 的 `android/.tooling`、用户 Gradle cache 或 Android build 目录中。`assembleDebug` 已成功，APK 的 `aapt` 静态检查确认 package 和唯一 permission 声明。

新安装的 ADB 实际执行 `adb devices -l` 只返回标题行，没有 `device`、`unauthorized` 或 `offline` 条目。收尾复核时，MTP `ingest --once --limit 1` 也返回 `devices=0`，所以无法在收尾阶段再次直接枚举手机源；这不改变先前已完成的 MTP 真机闭环，也不提供 APK 安装能力。因此本轮终态是：

`AUTOMATED_ANDROID_APP_INSTALL_UNAVAILABLE_IN_CURRENT_DEVICE_STATE`

这精确表示 **Windows 没有当前可用的标准自动 APK 安装通道**，而非 `READ_CALL_LOG` 已被 OPPO 拒绝，也不是 Android companion 路线已被判定不可行。MTP/WPD 是文件传输入口；它不能替代 ADB 或正常 Android package installer。本轮未开启开发者选项、USB debugging、root，也没有要求手工安装或把 APK 写入手机。

### USB debugging 已开启后的复核

在用户确认已主动开启 OPPO 的开发者选项和 USB debugging 后，本机立即执行了新的 ADB 检查：先直接读取 `adb devices -l`，再重启 Windows ADB server 后以 8 秒间隔重试三次。四次结果均只有 `List of devices attached` 标题行，最终 state=`NONE`；没有 `device`、`unauthorized` 或 `offline` 条目。Windows PnP 的非敏感摘要也没有当前 OPPO/Android/MTP 匹配对象，项目 MTP `probe` 同时返回 `devices=0`。

因此本次复核的精确终态是 `ADB_DEVICE_NONE`。它说明 Windows 当前没有枚举到可安装或可进行 RSA 授权的调试设备；不能据此判断“USB debugging 设置无效”，更不能把它改写为 `READ_CALL_LOG` 权限失败。没有 APK install、permission grant、appops、provider query 或 phone recording 写操作发生；现有 APK 重新 build 成功，Windows regression tests 为 `28 passed`。

| 阶段 | 当前真实状态 | 结论 |
| --- | --- | --- |
| JDK / Android SDK / ADB | `BOOTSTRAPPED` / `BOOTSTRAPPED` / `AVAILABLE` | Windows 命令行构建能力已真实建立。 |
| APK build | `PASS` | 最小 APK 成功编译，package/Manifest 已静态校验。 |
| APK install | `BLOCKED` | `adb devices -l` 的 device state=`NONE`，没有对 OPPO 发起安装。 |
| Manifest declared `READ_CALL_LOG` | `YES` | 是唯一声明的危险权限。 |
| runtime grant / flags / appops | `BLOCKED` | APK 未安装，不能从真机取得 package-manager 证据。 |
| `CallLog.Calls` provider | `BLOCKED` | app 从未在 OPPO 上运行，不能读取任何 call-log row。 |
| 190.028 秒 recording correlation | `BLOCKED` | 没有 provider row，故没有电话号码、direction、time delta 或 duration delta 的真机结果。 |
| probe cleanup | `NEVER_INSTALLED` | 本轮没有可用 ADB device，故未发生安装或卸载操作。 |

如果未来确实存在已授权 ADB 或另一种合法、自动的 installer，脚本会先拒绝覆盖同 package 的未知既有 App，再安装 debug probe、尝试正常 `pm grant`、收集 permission flags/appops、以围绕现有 event 时间的有界窗口（最多 20 rows）查询 `NUMBER`、`DATE`、`DURATION`、`TYPE` 和可选 cached name。原始结果只会留在 app-private file 并复制到 gitignored 的 `data_root/diagnostics/android-calllog-probe`；常规输出只保留号码掩码。完整 provider evidence 取得后，脚本会自动卸载 probe APK。

官方 API 文档说明 `CallLog.Calls` 包含 `NUMBER`、`DATE`、`DURATION` 与 `TYPE`；其中 `DATE` 是 epoch milliseconds、`DURATION` 是秒，且官方推荐用 URI limit 参数限制查询。[Android CallLog API](https://developer.android.com/reference/android/provider/CallLog.Calls) 官方 permission reference 同时将 `READ_CALL_LOG` 标记为 dangerous、hard restricted，并要求 installer allowlist；这在当前真机上尚未获得或拒绝，不能被静态 Manifest 结果替代。[Android permission reference](https://developer.android.com/reference/android/Manifest.permission.html)

Windows 侧关联器已经有合成测试：只有时间窗和时长窗同时命中且候选唯一时才给出 `HIGH_CONFIDENCE`；因当前 event 的时间 provenance 是 `wpd_modified_at`，即使未来唯一候选的时间差很小，也不会伪称 `EXACT`。真实 call row 尚未取得，所以没有把此逻辑用于 production event。收尾时无法重新枚举手机源，故“原手机文件仍在”的本轮最后一跳记为 `NOT_RECHECKED_AT_CLOSE_DEVICE_UNAVAILABLE`；但本轮没有任何手机文件写操作，也没有安装 APK。

## 三条路线比较与正式建议

| 路线 | 当前 OPPO | 销售额外操作 | 跨厂商性 | 作为客户匹配主键 |
| --- | --- | --- | --- | --- |
| 录音 filename / tag / WPD metadata | 当前无号码 | 无 | 低，厂商/版本差异大 | 不可作为主路线；仅可在多样本验证后作为 provisional 辅助证据。 |
| 普通 USB/MTP/WPD call log | 当前未暴露 | 无 | 低；MTP 公开对象由设备决定 | 当前不可用。 |
| 手机端授权 call-log component（feasibility source 已有） | 当前 APK build 已通过；真机安装通道被 ADB state=`NONE` 阻塞 | 需要一次合法安装、真实 runtime grant，并可能需要 installer allowlist | 高于文件名启发式，但仍须逐机型认证 | 仍是最可能提供时间、号码、方向并支持确定性关联的路线；当前 OPPO 尚未实测权限结果。 |
| 厂商官方备份/export（未来选择） | 本轮未发现当前可自动读取来源 | 往往需要用户导出 | 厂商特有 | 只适合作为显式人工/企业流程，不满足当前“只插 USB”。 |

未来如果手机端得到授权的 call log，再以最小窗口做 `recording ↔ call-log` 关联：需要时间距离、时长差、唯一候选三项同时满足，并输出 `EXACT`、`HIGH_CONFIDENCE`、`AMBIGUOUS` 或 `NO_MATCH`。若 filename 与 call log 号码冲突，必须标记 conflict、保留诊断证据且不填最终号码，不能静默覆盖。

## 对“大侠找光”链路的影响

当前 event 仍可稳定交给 downstream，但因为号码为 `NULL`，下游不能自动进入“电话号码 → 联系人 → 0..N 个候选项目”这一步。它仍可以处理媒体、时长、设备及时间 provenance，但不能自动客户匹配。

若业务必须在“销售只插 USB、无额外操作”条件下获得号码，当前样本仍没有可行证据。最小缺失能力仍是手机端一个经过明确同意、具备合规 `READ_CALL_LOG` 权限的轻量组件；本轮已经建立其最小源代码和 Windows 构建证据，但没有把它安装、集成或产品化。未来是否采用、如何分发、installer allowlist 与权限合规需要单独决策。

## 使用方法

```powershell
.\.venv\Scripts\python.exe -m sales_mobile_ingest investigate-identity
```

这会读取本机 ready media 和当前已连接手机中同一个 MTP source；不复制、改名、移动或删除手机文件。手机未连接时，本机媒体与 event 的只读检查仍可完成，但 WPD 与 MTP capability 结论会明确标记为不可用，而不会伪报成功。
