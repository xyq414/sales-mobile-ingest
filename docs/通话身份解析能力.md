# 通话身份解析能力

最后真实核验：2026-08-19。本文只陈述当前 OPPO A6 Pro 5G 的一个本机样本与普通 USB/MTP/WPD 传输模式的事实；不把它推广为所有 ColorOS 或 Android 设备的结论。

## 当前结论

当前这一条真实 OPPO 电话录音**未能可靠取得对方电话号码**。真实 event 保持：

| 字段 | 当前真实值 |
| --- | --- |
| `phone_number_raw` | `NULL` |
| `phone_number_normalized` | `NULL` |
| `phone_number_source` / confidence | `unknown` / `unknown` |
| `contact_name` | `NULL` |
| `call_direction` | `unknown` |
| `occurred_at_source` | `wpd_modified_at`（不是确定的通话发生时间） |
| `duration_source` | `wpd` |

`investigate-identity` 会对唯一 ready recording 执行受限只读调查。原始文件名、WPD property 值、音频 tag 值和邻近对象名称只写入 gitignored 的 `data_root/diagnostics/identity-investigation/*.raw.json`；命令输出及 `*.summary.json` 不包含这些原始敏感值。

## 方案 A：录音自身信息

当前样本结果：`DIRECT_RECORDING_PHONE_ID_NOT_FOUND_IN_CURRENT_SAMPLE`。

| 检查面 | 真实观察 | 号码结果 |
| --- | --- | --- |
| 原始文件名 | 仅记录了去标识化结构：basename 长度 19、一个 10 位数字段、`-` 分隔、无可严格解析的 datetime token | 没有符合保守电话规则的 token；10 位数字不能被当作对方号码。 |
| WPD / Shell | 可取得 `System.FileName`、扩展名、title/artist/album、size、modified time、duration、编码码率/采样率等；没有 `System.DateCreated`；Shell details columns 为 0 | 已检查可取得的身份相关属性，未发现号码候选；非空 title/artist/album 不被推断为联系人。 |
| MP3 内部 metadata | 本机只读 ID3v2 probe：未发现 ID3 tag | 没有号码、联系人或方向。 |
| 同目录 | 只枚举该 source 的直接父目录，观察到 1 个对象、无额外文件或目录 | 没有 sidecar、manifest 或可关联 metadata。 |

因此当前没有启用任何 OPPO filename-number parser，也没有改写真实 event。未来如果多份真机样本出现同一可验证格式，最多先以 `REAL_SAMPLE_PROVISIONAL` 引入，且需保留原始值、规范化值、source、confidence，并与其他证据交叉验证。

## 方案 B：通话记录关联

当前结果：`CALL_LOG_NOT_EXPOSED_VIA_CURRENT_MTP_WPD`。

本机对当前 WPD portable-device 根和唯一 storage 的第一层公开对象进行了有界读取：1 个 storage、14 个首层对象；没有暴露 call-history object、contacts object 或 backup/export object。此结论的准确含义是：**当前 sales-mobile-ingest 所使用的无侵入 USB/MTP/WPD 链路没有公开可供读取的通话记录对象**；并不表示手机没有通话记录，也不表示不存在其他需要用户操作或权限的导出方式。

Android 的正式 CallLog API 是应用内 `ContentResolver` 路线，`CallLog.Calls` 明确要求 call-log 权限；`READ_CALL_LOG` 是危险且受限制的权限。[Android CallLog API](https://developer.android.com/reference/android/provider/CallLog.Calls) [Android permission reference](https://developer.android.com/reference/android/Manifest.permission.html) 同时，Android 将 USB “文件传输”描述为 MTP 文件传输模式，而非向 Windows 暴露 CallLog provider。[Android developer options](https://developer.android.com/studio/debug/dev-options)

所以当前真实 190.028 秒录音无法做 call-record correlation：不是“时间附近找不到唯一通话”，而是在关联算法之前就缺少可读取的 call-log row（号码、开始时间、方向、联系人）。没有伪造 call-log reader 或匹配结果。

## 两条路线比较与正式建议

| 路线 | 当前 OPPO | 销售额外操作 | 跨厂商性 | 作为客户匹配主键 |
| --- | --- | --- | --- | --- |
| 录音 filename / tag / WPD metadata | 当前无号码 | 无 | 低，厂商/版本差异大 | 不可作为主路线；仅可在多样本验证后作为 provisional 辅助证据。 |
| 普通 USB/MTP/WPD call log | 当前未暴露 | 无 | 低；MTP 公开对象由设备决定 | 当前不可用。 |
| 手机端授权 call-log component（未来选择） | 本轮未实现 | 需要一次安装与 `READ_CALL_LOG` 等明确授权 | 高于文件名启发式，但仍须逐机型认证 | 最可能提供时间、号码、方向并支持确定性关联。 |
| 厂商官方备份/export（未来选择） | 本轮未发现当前可自动读取来源 | 往往需要用户导出 | 厂商特有 | 只适合作为显式人工/企业流程，不满足当前“只插 USB”。 |

未来如果手机端得到授权的 call log，再以最小窗口做 `recording ↔ call-log` 关联：需要时间距离、时长差、唯一候选三项同时满足，并输出 `EXACT`、`HIGH_CONFIDENCE`、`AMBIGUOUS` 或 `NO_MATCH`。若 filename 与 call log 号码冲突，必须标记 conflict、保留诊断证据且不填最终号码，不能静默覆盖。

## 对“大侠找光”链路的影响

当前 event 仍可稳定交给 downstream，但因为号码为 `NULL`，下游不能自动进入“电话号码 → 联系人 → 0..N 个候选项目”这一步。它仍可以处理媒体、时长、设备及时间 provenance，但不能自动客户匹配。

若业务必须在“销售只插 USB、无额外操作”条件下获得号码，当前样本没有可行证据。最小缺失能力是手机端一个经过明确同意、具备合规 `READ_CALL_LOG` 权限的轻量组件；是否采用、如何分发及权限合规需要下一轮单独决策。本轮不安装、不实现、不请求该组件。

## 使用方法

```powershell
.\.venv\Scripts\python.exe -m sales_mobile_ingest investigate-identity
```

这会读取本机 ready media 和当前已连接手机中同一个 MTP source；不复制、改名、移动或删除手机文件。手机未连接时，本机媒体与 event 的只读检查仍可完成，但 WPD 与 MTP capability 结论会明确标记为不可用，而不会伪报成功。
