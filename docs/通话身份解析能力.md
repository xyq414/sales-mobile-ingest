# 通话身份解析能力

最后真实核验：OPPO 证据 2026-08-19；Call-first synthetic implementation 2026-08-30。真机段落不推广为全部 Android、ColorOS 或 exporter 的事实。

## 当前结论

既有 ready recording-backed event 已通过用户创建的 SyncTech 公共 CallLog XML 得到受控 enrich；这是 2026-08-19 的真实 OPPO 证据。新主对象 `phone-call/v1` 直接来自 provider row，号码/联系人可为空，direction 与 disposition 分开，SIM provenance 独立保留。

录音文件自身仍未提供可用号码：文件名、WPD 属性和 MP3 ID3 tag 都没有可靠电话号码。普通 MTP/WPD 也仍未直接暴露 Android CallLog provider；有效来源是用户显式创建后可经 MTP 读取的公共 XML 文件。

## 真机关联证据

| 检查面 | 真实结果 | 使用方式 |
| --- | --- | --- |
| 录音媒体 | WPD duration 190.028 秒 | 保留 recording/event 的媒体 provenance。 |
| SyncTech XML | 1 条真实 `call` canonical row | `date`、`duration`、`type` 经真实 schema parser 读取；号码/联系人不输出。 |
| 时长 | 差 0.028 秒 | 通过时长窗口。 |
| 时间 | WPD modified time 不是确定通话发生时间；经本地时区偏移及录音结束时间对齐后差 3.208 秒 | 只形成 `HIGH_CONFIDENCE`，绝不形成 `EXACT`。 |
| 候选数 | 1 | 满足唯一性。 |

event enrichment 仍通过临时 JSON + `os.replace` 原子提交；媒体与 recording sidecar 均已存在且 hash 一致时才允许更新。新 PhoneCall/Link 也使用原子 JSON publication。重复 snapshot、两种 late-arrival 顺序和 restart 的 identity stability 已由 synthetic Golden Cases 验证。

## 来源边界

| 路线 | 当前 OPPO 证据 | 状态 |
| --- | --- | --- |
| 录音 filename / tag / WPD metadata | 无号码或联系人证据 | 不作为身份主来源。 |
| 普通 USB/MTP/WPD CallLog provider | 不公开 call-history 对象 | `CALL_LOG_NOT_EXPOSED_VIA_CURRENT_MTP_WPD`。 |
| 用户主动创建的 SyncTech 公共 XML | MTP 发现、复制、schema、parser、去重、关联、event enrichment 均真机通过 | `VALIDATED_EXTERNAL_CALLLOG_EXPORTER`。 |
| Android companion APK | 仅历史 build/Manifest 验证；未安装到手机 | 非当前优先路线。 |

## 设备、销售身份与下游

下游主边界是 `ready/calls` 和 `ready/call-links`；旧 `ready/events` 继续服务 recording-backed v1。Shell Path 只是 observed alias，registry 仅在 fingerprint 唯一匹配时认领 local `device_id`。销售归属来自非重叠有效期 assignment，并按 call occurred time 查询；未知设备不会继承 Windows、Git 或整机配置身份。

号码、联系人、SIM、assignment 和 raw XML 都只存在 gitignored data root/正式 downstream artifact，不进入普通日志或 Git。号码仍不能直接映射唯一 CRM 项目；下游必须产生 0..N 候选。

## 历史 Android companion 状态

`android/calllog-probe` 仍保留为隔离的历史 feasibility source：仅声明 `READ_CALL_LOG`，没有网络、录音、联系人或写入权限；APK 从未安装到 OPPO。此前 `adb devices -l` 为 `NONE`，这不是权限被 OPPO 拒绝的结论。当前项目不以 ADB 或该 APK 作为生产采集依赖。
